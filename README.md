# 자동차 경주

## 학습 목표

- 여러 역할을 수행하는 큰 함수를 단일 역할을 수행하는 **작은 함수로 분리**한다.
- **테스트 도구를 사용하는 방법**을 배우고 프로그램이 제대로 작동하는지 테스트한다.
- **1주차 공통 피드백**을 최대한 반영한다(커밋, 디버깅, 네이밍,주석, 포매팅, Java API, 컬렉션 등)
- **1주차 PR 리뷰 피드백을 최대한 반영한다**
    - 클래스명과 변수명 좀 더 구체적으로 적기
    - **디미터 법칙 준수하여 결합도 낮추고** 메서드 명 신경쓰기
    - 코드 포매팅 의식하기 (띄어쓰기, 공백 등)
    - **테스트 코드 작성 시 메서드 명 구체적으로** 작성  (`@DisplayName`)
    - 역할과 책임 측면에서 도메인과 메서드가 꼭 필요한 포인트인지 생각해보기
    - var 를 사용할 때에는 명확하게 타입 추론이 되는 상황인지 신중히 생각하고 사용하기
    - SRP 좀 더 생각해보기, SRP를 잘하면 ValueObject나 DTO가 필요 없을 수도 있다.

## 기능 요구 사항

초간단 자동차 경주 게임을 구현한다.

- 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.
- 각 자동차에 이름을 부여할 수 있다. 전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다.
- 자동차 이름은 쉼표(,)를 기준으로 하며 이름은 5자 이하만 가능하다
- 사용자는 몇 번의 이동을 할 것인지를 입력할 수 있어야 한다.
- 전진하는 조건은 0에서 9 사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우이다.
- 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. 우승자는 한 명 이상일 수 있다.
- 우승자가 여러 명일 경우 쉼표(,)를 이용하여 구분한다.
- 사용자가 잘못된 값을 입력할 경우 `IllegalArgumentException`을 발생시킨 후 애플리케이션은 종료 되어야 한다.

## 추가된 프로그래밍 요구사항

- indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.
- 3항 연산자를 쓰지 않는다.
- 함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- JUnit 5와 AssertJ를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.

## 구현 기능 목록

- [X] 랜덤 함수를 실행하여 4이상의 값인 경우 true를 리턴
- [X] 입력받은 문자열 파싱
    - [X] 첫번째 입력으로부터 차 이름 리스트로 파싱
        - 구분자 기준으로 분할
        - 구분한 문자에 빈 값이 없는지 검증
        - 분할한 문자가 5글자 이하인지 검증
    - [X] 두번째 입력으로부터 시도 횟수 정수 파싱
        - 빈 값은 아닌지 검증
        - 음수 값은 아닌지 검증
- [X] 이름 리스트에 중복이 있는지 검증
- [X] 자동차 팩토리
    - 이름 값을 입력받아 자동차 생성
    - 생성한 자동차 일괄적으로 관리하는 일급 콜렉션 생성
        - 자동차 생성 메서드를 중복 없는 이름 리스트 수만큼 반복하여 생성
    - [X] 자동차 개별 클래스
        - 이동하여 값 증가
        - 이동한 상태(이름: 값 형태) 출력 요청
    - [X] 자동차 리스트
        - 생성자로 주입받아 자동차 리스트 생성
        - 랜덤 함수 확률 게이트에서 처리된 자동차들 이동시키기
        - [X] 모든 자동차에 대한 정보 출력
            - 자동차 클래스 현황 체크용 프린트 Port 분리
            - 해당 클래스에 대해 요청하는 메서드만 콜렉션에서 보유
        - 가장 멀리 이동한 차량 찾기
- [X] 게임 컨트롤러
    - 이동할때마다 이동 현황 출력
- [X] 사용자 입력 처리
    - 입력 제대로 들어왔는지 검증
- [X] 게임 우승자 출력
